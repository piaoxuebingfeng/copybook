# 拼音字帖设计说明

汉字字帖（田字格 + 笔顺）之外的第二条生成线：**四线三格拼音字帖**。
本文记录已定的设计、踩过的坑，以及形态演进的来龙去脉。

---

## 一、形态：v1 → v2（2026-10）

**v1（已废弃）**：「一行一个音节」——整行是一条四线格，音节整行描红。
看完 v1 成品后确认了两个问题，都指向**换字体**和**换格子结构**：

1. *「字母和字母之间的间距稍微有点大，部分字母之间的间距也不是等宽的」*
2. *「当前的拼音的描红的字体，存在部分拼音不是手写出来的，比如字母 g」*

**v2（当前）**：参考开源工程 **Copybook**（Flutter，BSD-3）的拼音字帖格式，
改成「**一方格一个音节**」：

```
【拼读】　shàng　上
┌──────┬──────┬──────┬──────┐
│ shàng│ shàng│ shàng│ shàng│   ← 首格黑色示范，其余浅灰描红（默认整行）
└──────┴──────┴──────┴──────┘     浅绿实线外框+竖分隔，中间两条更浅的虚线
```

- 每个音节占一行格子：**首格黑色示范（`#222831` 附近的墨色）+ 其余格浅灰
  描红（`#CECECE`）**，格与格之间浅绿竖实线
- 线色是参考工程成品的实测值：实线 `#92E892`、虚线 `#CAF1CA`
- 默认整行描红（`--trace-times=full`），也可以只描 N 格、其余留白给孩子自己写
- 每行上方是标签行：`【组名】　shàng　上`（汉字由 Excel 黑体渲染，不进拼音字体）

| 方案 | 说明 | 状态 |
| --- | --- | --- |
| A. 一行一个音节（整行描红） | v1 形态 | 已被 v2 取代 |
| **D. 一个音节一个方格 + 首格示范** | 参考 Copybook 工程的格式 | ← **v2，已实现并验收** |
| B. 汉字 + 拼音对照（看拼音写汉字） | 参考工程有此模式；需要词典、多音字 | 备选，未实现 |
| C. 一格一个字母（`b` / `ā` 分开练） | 适合刚学字母阶段 | 备选，未实现 |

### v1 当年「为什么不用方格」的顾虑，v2 怎么解的

v1 的理由：`zhuāng` 6 个字母在 2.38cm 方格里放不下，硬塞就得缩字号，
**字号一缩 x-height 就不再等于一条带**，字母立刻脱离四线格。

v2 的解法是**格宽自适应、字号绝不缩**：

```
格宽 = max(最小格宽 90px, 最长音节墨迹宽 + 2×边距)
列数 = floor(总宽 720px / 格宽)        ← 格宽整除进 19.05cm
```

于是 `zhuāng` 进来时格变宽（列数变少），字母仍按「x-height = 一条带」的
标准字号坐在带上。格宽**整本统一**（不逐行变），行列还是整齐的。
这是从「格子整齐优先」到「带对齐优先」的一次立场修正——四线三格的教学
价值全在带界上，格宽只是容器。

## 二、两个 v1 问题的根因：字体（这是本轮最大的教训）

### 问题 ②：`g` 不是手写体

v1 用系统楷体（simkai）。它的 `g` 是**双层**（double-storey，两个封闭腔），
是印刷罗马体的造型；低龄拼音教学里写的是**单层** `g`（一笔画下来的样子）。

判定方法不用肉眼、也不依赖字体名：**字形墨迹的封闭腔数量**。把字形按
bbox 撑开画出来，从边框外洪泛填充背景，数被墨迹围起来的封闭空腔——
双层 `a`/`g` 是 2 个腔，单层是 1 个（`b d e o p q` 天然 1 个，`ǎ` 顶多 2 个）。
这个判据在 simkai（g=2 腔）、汉语拼音.ttf（g=1 腔）上都验证过。

- **首选字体换成「汉语拼音.ttf」**（参考 Copybook 工程自带，专为拼音造，
  `a`/`g` 天生单层）—— 从根本上解决
- **兜底替换**：如果只能用双层字体（如 simkai），自动把 `g`→`ɡ`（U+0261，
  单层拉丁字母）、`a`→`ɑ`（U+0251）—— 仅当替换目标在字体里存在时才换，
  换不动的照原样（宁可双层也不渲染豆腐块）

### 问题 ①：字距又大又不匀

测出来的数据（x-height 30px 的字号下，相邻字母墨迹间的空隙）：

| 音节 | simkai | 汉语拼音.ttf | 参考工程成品 |
| --- | --- | --- | --- |
| `wǒ` | 21px（0.70×带） | 5px（0.17×带） | 4~5px |
| `shàng` | 8/21/23/6（忽宽忽窄） | 5/7/6/6（均匀） | 均匀 |

根因：**带调元音的侧架（side bearing）在楷体里特别肥**——同一个 `a`，
带调的 `à` 比不带的 `a` 两边各多出好几个单位的空白，于是声调落在谁头上、
谁左右的缝就变宽。`wǒ` 的 `o` 带上声后两边共多出 ~16px。
这是字体度量的属性，**排版端调 letter-spacing 修不好**（会把不带调的字母
挤得更紧，不匀只是换个位置不匀）。

换成汉语拼音.ttf 后（i=0.23em、l=0.20em、主体 0.40~0.63em 的窄匀字面），
字距自然收紧到和参考成品一个量级——**两个问题一次解决，都没动排版代码**。

### cmap 的坑：`getBestCmap()` 会漏字符

汉语拼音.ttf 的 cmap 有 3 张子表：(0,3) 1417 映射、(1,0) Mac Roman 226 映、
(3,1) 1421 映射。**`a-z` 和声调字符在 (1,0) 里**，而 fontTools 的
`getBestCmap()` 只挑一张「最好」的子表 → 报告 a-z 全缺。
v1 的覆盖校验因此差点把这个字体判死刑。

教训：**覆盖校验必须合并所有 cmap 子表的键**再查（`_merged_charmap`），
不能信单一入口的「最佳」视图。PIL 渲染本身倒是三张表都认。

### 字体策略（不变的部分）

1. 优先级：`fonts/` 里**名字带「拼音/pinyin」的字体优先** → 系统楷体 →
   AR PL UKai → Noto CJK → …
2. 运行时校验覆盖（合并子表版）：缺哪个字符明确报出来并中止
3. 仓库**不内置任何字体**——包括汉语拼音.ttf：参考工程的代码是 BSD-3
   可借鉴，但**字体文件没有随附许可证**，不能跟着我们的仓库分发。
   获取方式见 README「字体准备」一节

## 三、四线三格的几何

### 格子结构：3 个子行，不是 2 个

田字格用 **2×2 子单元格**画「外框 + 内部十字」。四线三格有 **3 条等分带**，
2 个子行表示不了 3 等分：

```
田字格：  SUB_PX  = 45px  ->  CELL = 90px = 2.38125cm   （2 子行）
四线三格： SUB3_PX = 30px  ->  CELL = 90px = 2.38125cm   （3 子行，每带 30px）
```

两条生成线的格子边长恰好相同（2.38125cm）：整数像素里能同时被 2 和 3 整除
的最小值是 90。总宽（v2 按格宽×列数）仍收敛在 720px = 19.05cm。

四线三格用**原生 Excel 边框**画：上下浅绿实线 + 竖分隔实线（外框语言），
中间两条更浅的虚线（辅助线）——外实内虚，与汉字字帖的视觉语言一致，
线色取自参考工程成品的实测值。

### 字母要「坐」在正确的带上

三条带分工固定：上带放升部与声调、中带放字母主体（x-height）、下带放降部。
做法：

1. **实测** `x` 的墨迹高度，反解字号使 x-height 恰好等于一条带（不信字体度量）
2. 用 `anchor="ms"` 把**基线钉在框高的 2/3 处**（即第二条虚线上）
3. 墨迹在格内**水平居中**（先量 scratch 图的 bbox 再平移起点，不用 advance
   居中——advance 里含侧架，会把带调元音挤歪）
4. 贴图**纵向零内缩**、高度**正好等于三行子行之和**——差 1px 图里的带界
   就和 Excel 画的虚线错开，字母整条带地偏，且不报错

换用汉语拼音.ttf 后重测（框高 90px）：`x`/`o` 墨迹 30.0~59.8（正好占满中带），
`b`/`l` 顶到 13.2（进上带），`g` 底到 72（进下带），20 个带调字符顶 12.8~21
（声调全部进上带）——全格通过。

## 四、输入格式

沿用「一行一组、`组名: 音节表`」的写法：

```
一组: bā 八 / mā 妈 / bà 爸 / mǎ 马
二组: xiǎo 小 / shàng 上 / xué 学 / lǎo 老 / shī 师
```

- 声调用**预组合字符**（`ā á ǎ à`），不要自己叠——叠加符号的位置会漂，
  不同字体漂得不一样
- 也支持**数字标调**：`ba1`→`bā`、`ma3`→`mǎ`、`ma5`→轻声、`nv3`→`nǚ`。
  标调位置按《汉语拼音方案》：`a o e` 优先，`iu/ui` 标后者，否则标在唯一元音上
- 音节后可跟一个汉字做标注：`bā 八`（汉字不参与拼音字体的覆盖校验——
  拼音专用字体往往只有拉丁字符）
- **非法音节会被拦下**（如 `ba9`）：不拦的话会原样渲染成一个带数字的假音节

## 五、验收方式

**逐格验收**（`python3 verify_pinyin.py 字帖.xlsx --chars="…" --pdf=字帖.pdf`），
xlsx 层 + PDF 层共九道，每道都能独立把「看着差不多但其实是错的」抓出来：

| # | 查什么 | 为什么必须查 |
| --- | --- | --- |
| 1 | 四线格数量 = 音节数（按边框特征识别，不认行号） | 少一个音节不报错 |
| 2 | 三带等高、子行高 = 整数量化值 | 带界错位字母整条带偏 |
| 3 | 每行格数 = 规划列数 | 列宽漂了格宽就不对 |
| 4 | 贴图纵向零偏移、高度 = 三子行之和、**超出描红范围的格必须无图** | 同 2；多贴图是常见手误 |
| 5 | 逐格**按像素内容**反查角色：首格=示范黑、格 1..N=描红灰 | 贴错图/角色贴反/内容与渲染意图不符 |
| 6 | 标签行含对应音节 | 音节和标签错位 |
| 7 | PDF：每带四条线，虚线严格三等分（≤3px@200dpi） | 导出层的带界必须和排版层一致 |
| 8 | PDF：竖分隔线数量对、间距均匀 | 列宽标定在导出层漂没漂 |
| 9 | PDF：逐格墨迹范围与**渲染意图**一致 + 首格深其余浅 | 端到端落带；示范/描红角色印对了 |

两个判据层面的教训：

- v1 曾写「墨迹底部 ≈ 2/3（基线）」，把 `shàng` 的 `g` 降部判成了错的——
  **判据错了不是产物错了**，一律改用「与渲染意图一致」
- 意图侧的墨迹框必须用 alpha>40（看得见的墨）：LANCZOS 的半透明羽边在
  PDF 里渲染成近白色，两侧口径不一致会永远差几像素
- PDF 分带不能按「带间距大于带内线距」分组——标签行+间隔行只比一条带宽
  窄一点；要按 [实,虚,虚,实] 的**线型模式**切

> 与汉字那侧的五道验收（笔画数据/教学条像素/逐格排布/PDF 几何/教学条宽度）互补。

## 六、模块划分

```
sheet_layout.py      共享版面层（两条生成线共用）
pinyin_input.py      音节表解析、数字标调、合法性校验（无词典）
render_pinyin.py     字体探测（合并 cmap）+ 单/双层判定与 ɡ 兜底 + 单格渲染 + cell_plan + CLI
generate_pinyin.py   单元格排版：自适应格宽 + 原生四线格边框 + 示范/描红贴图 + 分页
verify_pinyin.py     九道逐格验收
zitie_gen.py         总入口：--type=pinyin（默认 hanzi）
```

`cell_plan` 是格宽自适应的唯一实现，渲染与排版**各自以相同输入重算并互相
印证**（对不上直接中止）——同一份几何有两处使用方，漂了比错了更隐蔽。

汉字那侧的四个渲染模块（`render_strokes` / `render_trace` / `stroke_lib` /
`stroke_store`）完全没有被改动，继续只服务汉字笔顺。
