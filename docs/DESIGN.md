## 田字格是怎么在 Excel 里画出来的

Excel 没有「田字格」这种单元格，全部靠边框拼：

* 一个田字格 = **2×2 个子单元格**：外圈用绿色实线（`00B050`），内部那一条横线和一条
  竖线用灰色虚线（`999999`）—— 合起来正好是标准的田字格十字。
* **绝不能合并单元格**。合并 2×2 会**删掉内部十字**（实测合并后内部灰线像素为 0），
  所以描红不写进单元格，而是用**透明背景 PNG 叠加**在格子上，任何软件里十字都完整。
* 格子尺寸按**整数像素**定义（1px = 0.75pt @96dpi）。按厘米写会得到 45.35px，
  列宽能精确到 45.35px，但行高最小单位是 1px、会被取整成 46px —— 格子就成了
  1.217 × 1.190cm，不是正方形。所以先定 `SUB_PX=45` 再反推列宽。

| `-h` / `--help` | 显示全部参数说明 | — |

## 字表文件格式

以 `#` 开头是注释；可以纯字表，也可以分组（`组名: 字表`）：

```
# 我的字表
基础数字: 一二三十
自然方位: 上下左右大小多少
```

程序会自动跳过空白、逗号、标点，并去重后按顺序排版。

## 覆盖范围与限制

* 字库来自 **hanzi-writer-data 2.0.1**（源自 Make Me a Hanzi），共 **9575 字**
* 抽查：一年级常见生字 **44/44** 有数据；简体常用字 **26/26** 有数据
* 极生僻字（如 龘、齉、麤）没有数据，程序会**提示并跳过**，其余字照常生成
* 标点符号不在字库里（字帖也用不到）

**教学条永远不宽于田字格。** 单行最多 7 格，上限 16cm（= 田字格宽度）：

| 笔画数 | 教学条 |
|---|---|
| ≤6 画 | 单行，最宽 14.72cm |
| 7~13 画 | 2 行，条高 4.95cm，最宽 14.60cm |
| 14 画以上 | 3 行（18 画的「鹰」） |

* 实测所有字帖的**最右墨迹 = 16.80cm，正好是田字格右边缘**——教学条不会伸到格子区外面
* 换行时会**把上一行最后一格带下来作伴**，不会出现"最后一行只有孤零零一个描红格"
* 分页按**实际高度**计算，绝不会把某个字切到两页

> 为什么宁可换行也不让条变宽：教学条一旦宽于田字格，就会超出打印区域，
> **在导出 PDF / 打印时被静默裁掉**（这个 bug 真实发生过，见下方「关键设计」第 3 条）。
> 想让条更宽、少换行的，可以调 `--strip-max-cm`。

## 调节

改一处参数即可重出，无需改代码：

* **笔画粗细** — `--thin=N`，1024 数据盒坐标单位。实测安全上限 **10**（再大「右/耳/间」的细横会被压断，程序会自动自检并报警）。调小更接近字本身的样子。
* **版式** — `--layout=a5`（2 字/页，默认）/ `--layout=a4`（4 字/页）
* **方向** — `--orient=portrait`（纵向，默认）/ `--orient=landscape`（横向）
* **格子大小** — `--cell-cm=`（a5 默认 2.4、a4 默认 2.0；实际会取整到整数像素）
* **描红格数量** — `TRACE_CELLS`（默认 3）
* **每行格子数** — `CELLS_PER_ROW`（默认 8）
* **标题/页边距** — `MARGIN_CM`（默认 0.8cm）

## 关键设计与踩过的坑

每一条都是实测出来的，不是猜的。

1. **绝不合并单元格**。合并 2×2 单元格会**删掉田字格内部的十字虚线**（实测合并后内部灰线像素为 0），所以田字格由 4 个子单元格拼边框实现；描红用透明背景 PNG 叠加，任何软件里十字都完整。
2. **教学条用字形轮廓填充，不是描边**。数据里的 `strokes` 是笔画的**外轮廓闭合路径**（`medians` 才是中心线）。早期用粗笔描外轮廓，实际线宽 = 字形厚度 + 笔宽，所以怎么调都偏粗；改成直接填色后才是字的真实样子。
3. **教学条不能宽于田字格**。田字格 16cm 宽，打印区域也是 16cm；教学条一旦超出，**超出部分在导出 PDF / 打印时会被静默裁掉**（实测 16.95cm 的「间」被裁到 16.02cm、16.82cm 的「季」被裁掉整整一个描红格，页面几何检查完全察觉不到）。所以直接把教学条限制在 16cm 以内——最稳妥，也最好看。
   * 另注：打印区域若宽于 19.4cm 可打印宽度，`fitToWidth` 会**把整页缩小**，格子就不再是 2cm 了。
4. **合并单元格会静默裁掉超出宽度的文字**。表头原本把"姓名/日期"和"看图说明"挤在同一行，实测 16.06cm 而合并宽度只有 16cm，尾部被裁。现在拆成两行，并且 `generate_zitie.py` 里加了 `check_text_width()` 自检——标题或说明文字一旦超宽会**直接告警**，不会再默默裁掉。
5. **田字格尺寸必须按整数像素定义，不能按厘米**。行高的最小单位是 1px（0.75pt @96dpi）。按 1.2cm 定尺寸会得到 45.35px，列宽精确到 45.35px 但行高被取整成 **46px** —— 于是格子是 1.217 × 1.190cm，**不是正方形**。改成先定 `SUB_PX=45`（整数像素）再反推列宽，Excel 与 LibreOffice 两边都是精确 90×90px = 2.38125cm 正方形。
6. **两张 A5 必须严格等高**，否则从正中裁开会一大一小。而且这里有个隐蔽坑：Excel 与 LibreOffice 对行高的取整方式不同，用非 0.75pt 整数倍的行高会**逐行累积偏移**，十几行后裁切线能偏出几个毫米。所以每一半的内容高度都**精确补齐到 396.0pt**（纵向）/ **547.5pt**（横向），并且所有行高都是 0.75pt 的整数倍。实测每一半都恰好是这个值（纵向 396.00pt、横向 547.50pt）。
7. **横向版式左右两半共用同一批行**。纵向时两张 A5 是**上下叠**的（行不同、列相同），可以一半一半顺序生成；横向时是**左右并排**（行相同、列不同），两半必须共用行 —— 所以教学条行高取两半中较高者、田字格行数也必须一致，否则左右两张 A5 会不一样高。`build_a5_landscape()` 把两半放进同一次循环里就是为了这个。
8. **打印区域一旦超过可打印宽度，`fitToWidth` 会悄悄把整页缩小**。横向版式是"两张 A5 正好铺满 A4 宽"，打印区域宽度天然等于可打印宽度，差一点点就会触发缩放 —— 实测内容算成 28.8cm（可打印只有 28.1cm）时，整页被缩到 97.2%，格子从 2.38125cm 变成 2.32cm，裁切线也从 14.85 跑到 14.44cm。现在最外侧那条留白**故意收窄 0.1cm**（打印区域 28.0cm），留出安全余量，实测格子与裁切线都精确。
9. **验收工具不能写死版式**。`verify_pdf.py` / `verify_strips.py` 原来把"格子 2cm、一行 8 格共 16cm"写死，换版式后立刻误报。现在全部**从 PDF 实测**：纸张尺寸、格子边长、每页几个田字格块都现场量，格子行数用 `--cols=` 告诉它（纵向/A4 = 8，横向 = 5），描红格位、格高筛选范围按实测边长缩放。三种版式共用一套工具。
10. **教学条那一行会被误判成田字格行**。教学条图片用的是**同一个绿色**画格子框（风格统一），它上下边缘同样是长绿线；而"字头行高 + 教学条高"恰好也是一个格子高，于是整条教学条被当成一行田字格，里面的粉色描红示范格被算成"描红行"，验收就多报一行。用灰色内部十字区分也不行（教学条里的田字格框本来就有灰十字）。最终靠**结构特征**解决：田字格是一行挨一行铺开的，它的横线必然构成一条**等间距等差数列**，教学条那两条边框凑不进序列 —— 取所有长度 ≥3 的序列即可。

## 笔顺练习模式的排布算法

`--stroke-order` 打开后，每个字的田字格由 `generate_zitie.stroke_order_plan(n, m)` 排出：

- `n` = 笔画数，`m` = 这个字分到的田字格数（= 田字格行数 × 每行格数）
- 理想排布：`[1..n] × 3 遍` + `整字 × 3` + 留白，恰好用满 `m` 格
- 放不下就按固定顺序降级：`(3,3) → (3,2) → (3,1) → (2,3) → … → (1,1)`，
  **先减整字个数、再减笔顺遍数**，优先保证笔顺练到
- 连 `(1,1)` 都放不下（`n + 1 > m`，例如 15 画的字只有 8 格）时，把一遍笔顺
  均匀压缩进前 `m-1` 格：第 1 格给第 1 笔、第 `m-1` 格给全部 `n` 笔
  （`1 + round((k-1)(n-1)/(m-2))`），最后一格放整字

格子的内容渲染复用 `render_trace.render_stage(ch, k)`，实质就是
`stroke_mask(ch, range(k))` —— 和整字描红同一套轮廓填充管线、同一减细量，
所以**字形与位置完全同源**，只是画的笔数不同。

铺排时「格号 → 位置」的换算：`行 = 格号 // 每行格数`、
`列 = 块起点 + 2 × (格号 % 每行格数)`（一个田字格占 2 个子列）。
纵向 A5 / 横向 A5 / 紧凑 A4 三种版式共用这段代码。

> **一个必须知道的等价关系**：第 `n` 阶段（画满全部笔画）与整字描红的像素**完全相同**。
> 所以「笔顺第 3 遍的最后一格」和后面重复的整字看起来一模一样 —— 这是对的，
> 校验脚本也把两者当同一个符号对待，不算差异。

## README 里的示例配图怎么来的

`docs/` 下的示意图不是手工画的，是**从真实产物 PDF 渲染 + 程序化标注**生成的：

```bash
python3 docs/make_docs_images.py
```
